# ロールを作る・直す

`make create` は雛形と `FIXME` を置くところまでしかやらない。**その `FIXME` を埋めるのがこの手順**。

新規作成でも既存ロールの手直しでも同じ手順を使う。**入口はどちらでもよい** —— `roles/<ROLE>/` がまだ無ければ作るところから、既にあればその先から始める。

このリポジトリは AI 無しで動くことを要件にしている（[ADR 0006](../../../docs/adr/0006-tool-works-without-ai.md)）。だからこの手順は**人が読んでも同じことができる形**で書いてある。ツールに AI を組み込まない代わりに、ここに置いている。

## 手順

### 1. 雛形を置く（無ければ）
```
make create ROLE=<ROLE>
```
既に `roles/<ROLE>/` があるならこれは飛ばす。**既存ディレクトリがあると `make create` は `[ERROR] ... is already exists.` で止まる**ので、先に有無を見ること。

### 2. `install.sh` を書く
雛形にはよくある導入方法がコメントで並んでいるので、該当するものを外して使う。

- **冪等にする。** 何度流しても同じ結果になること。`brew list <name> > /dev/null 2>&1 || { brew install <name>; }` の形が基本
- 設定ファイルは `cp -fr` で `${HOME}` へ配る。zsh の設定（環境変数・alias・その他）を持たせるなら `roles/<ROLE>/.zsh.d/` に置く。**命名・読み込み順・落とし穴は [docs/zsh-config.md](../../../docs/zsh-config.md) が正**（雛形に `.zsh.d/` は含まれないので、必要なロールだけ自分で作る）
- **更新のための仕組みは作らない。** 更新も install を流し直すことで行う（[ADR 0005](../../../docs/adr/0005-install-only-no-update-hook.md)）

### 3. `README.md` を書く

**2 行目が最重要。** `make list` の説明欄にそのまま出る。

```markdown
# roles/<ROLE>
<日本語 1 行。何のツールか。全角 30 字程度>
```

- **日本語で書く。** 上流のタグラインや GitHub のリポジトリ説明を貼らない（英語で長く、一覧が読めなくなる）
- 長いと `make list` の桁が崩れる。全角 30 字程度に収める
- 1 行目と 2 行目の間に**空行を入れない**（`sed -n 2p` で拾っているため、空行だと説明欄が空になる）

残りの節はこう書く。

- **`## Dependencies`** — このロールより先に入っている必要があるものを書く。インストール順を考えるときの入力になる。無ければ `- nothing`
- **`## Usage`** — **思い出せる／調べるキッカケになる**程度。詳しい説明は要らない
  - CLI なのか GUI なのかが分かること
  - よく使う操作を 2〜3 行。自分がよく使うもの、忘れがちなものを優先する
  - 網羅しない。詳しくは `## References` へ誘導する
- **`## References`** — 上流の URL。公式サイト・GitHub・ドキュメント

ロール固有の事情（手動で残る設定、コード化できない理由、設定項目の一覧など）があれば節を足してよい。`roles/hammerspoon/README.md` が参考になる。

### 4. `roles.lst` に登録する
**忘れると `make install`（`ROLE=` 無しの一括）の対象から静かに漏れる。** ロールを削除したときも同様に消す。

### 5. `archives/roles/` を確認する（新規作成のとき）
同名・同目的の旧ロールが残っていないか見る。あれば原則削除する（本採用したので不要。必要になれば git 履歴から復元できる）。ただしインストール方法などが本採用版と違って参考になりそうなら、**中身を比較のうえ**残す判断をする。削除前に必ず差分を確認すること。

### 6. `make doctor` を通す
```
make doctor
```
`roles.lst` への登録漏れ、`README.md` の 2 行目が空／`FIXME` のまま、`install.sh` の欠落を見る。**`[OK]` が出るまで終わりにしない。**

### 7. 実際に流して確かめる
```
make install ROLE=<ROLE>
```
**2 回流して同じ結果になることを確認する**（冪等性）。1 回目で通っても、2 回目で `already exists` 等で落ちる書き方は珍しくない。

## やらないこと

- **`make` から `claude` を呼ばない。** このツールは mac の初期状態から流す前提で、`claude` はこのツールが入れる対象の 1 つ。ツールが AI に依存すると循環する（[ADR 0006](../../../docs/adr/0006-tool-works-without-ai.md)）
- **`update.sh` を作らない。** 更新は install を流し直す（[ADR 0005](../../../docs/adr/0005-install-only-no-update-hook.md)）
- **上流の成果物を repo に同梱（vendor）しない。** 設定は自分の側に持ち、本体は install 時に取得する。同梱するのは、自分で改造していて repo の中に資産がある場合だけ

## 既存ロールをまとめて直すとき

2 行目の書き直しのように複数ロールを横断する作業では、**1 ロールずつ「読む → 書く → `make doctor`」を回す**。まとめて書いてから最後に確認すると、どこで崩れたか分からなくなる。

一行説明を書くときは、そのロールの `README.md` 全体と `install.sh` を読んでから書くこと。**上流の説明文を訳すのではなく、「自分がなぜこれを入れているか」が伝わる 1 行にする。**
